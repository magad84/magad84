# Public Repository Readiness Checklist

Use this checklist before a repository is promoted on the GitHub profile or pinned as selected work.

## Brand & Positioning

- Repository title and description are clear to a non-developer audience.
- README explains the business problem, user, value, and current status before technical detail.
- Public wording aligns with the approved Mostafa Gad executive positioning.
- No unsupported claims, inflated capabilities, or unapproved branding.

## Confidentiality & Commercial Protection

- No secrets, credentials, tokens, private URLs, internal infrastructure details, or confidential records.
- No proprietary prompts, protected datasets, internal evidence archives, or commercial implementation that should remain private.
- No content copied from private repositories unless explicitly approved for public release.

## Product Presentation

- Clear purpose and target user.
- Clear capabilities and limitations.
- Screenshots or visual evidence only when approved and current.
- Current implementation status is not overstated.
- Roadmap items are clearly separated from delivered functionality.

## Documentation Quality

- README is concise and professionally structured.
- Links work and point only to approved public destinations.
- Repository governance and contribution expectations are clear where needed.
- Public documentation does not depend on private chat history for interpretation.

## Technical Hygiene

- No sensitive configuration files or generated secrets.
- Public branch is coherent and not an accidental development snapshot.
- License and reuse terms are deliberate where applicable.
- Issue and PR history does not expose material that should remain private.

## Promotion Decision

A repository should be pinned only when it passes the checklist and materially strengthens the public profile.
